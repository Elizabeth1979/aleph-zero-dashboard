System Architecture

How your Hermes setup receives requests, reasons with models and tools, stores context, runs automations, and publishes results.

Scroll sideways on a small screen. Lines show the main request and data paths; dashed lines show background synchronization.

Request lifecycle

  1. A message or schedule creates a session request.
  2. The runtime builds context from rules, memory, skills, and history.
  3. The model selects actions; Hermes runs and verifies tools.
  4. The result returns to the originating interface.

Model routing

  • Primary: GPT-5.6 via OpenAI Codex.
  • Short requests may use GPT-5.4.
  • Fallbacks use OpenRouter, then local Ollama.
  • Local vision uses Ollama.

Data boundaries

  • Operational state lives under ~/.hermes/.
  • Secrets stay outside the public dashboard.
  • The dashboard receives generated, redacted data.
  • GitHub Pages serves the static website.
